# TENSEI — локальное выделение рукописных строк и ячеек

## Два локальных уровня

1. **OpenCV (CPU)**: ищет реальные длинные горизонтальные и вертикальные линии, пересечения и прямоугольные ячейки; возвращает координаты в долях 0–1. Работает без GPU, Cloud.ru и скачивания нейросетей. На таблицах без линий честно возвращает пустой результат.
2. **PP-StructureV3 (модель структуры документа)**: обнаруживает ячейки и в таблицах со сложной или неполной разметкой. По возможности уточняет сетку OpenCV. Это **локальный, но требовательный к ресурсам** вариант; нужен подходящий PaddlePaddle/PaddleOCR runtime.
3. **PP-OCRv6**: распознаёт локальные фрагменты текста и отдаёт реальные координаты текстовых областей. Текст привязывается к ячейке, только если координатный центр лежит внутри её границ.
4. **PaddleOCR-VL**: дополнительный локальный анализ сложных страниц; пока результаты носят диагностический характер и не заменяют проверенные данные.

Это не гарантированно самый точный OCR для всех рукописных журналов. На реальных фото требуется сравнение с разметкой оператора.

## Минимальный локальный запуск, без PaddlePaddle

На Windows:

```powershell
py -3.11 -m venv .grid-venv
.grid-venv\Scripts\python -m pip install -r scripts/grid-requirements.txt
.grid-venv\Scripts\python scripts/paddle_service.py
```

После запуска сервис принимает только локальные подключения на `http://127.0.0.1:8765`. В TENSEI загрузите фото и нажмите **«Найти строки и ячейки локально»**. Это вызывает `POST /api/layout` → локальный `POST /segment` без запроса к Cloud.ru. Зелёных подтверждений правильности данных эта операция не создаёт.

## Мощная гибридная обработка

Установите подходящий PaddlePaddle по официальной инструкции для вашего CPU/GPU и пакеты из `scripts/paddle-requirements.txt`. В TENSEI включите **PaddleOCR — разметка таблицы** и/или **OpenCV — точная сетка строк и ячеек**. Для рукописного OCR включите **PP-OCRv6**; PaddleOCR-VL включайте отдельно, если ресурсов достаточно.

`/analyze` использует PP-StructureV3 с геометрической проверкой OpenCV; `/ocr` отдаёт найденный текст и его координаты, а также диагностическое сопоставление текста с ячейками. `/vl` отдаёт непроверенный результат VL. Все дополнительные функции необязательные; неустановленные модули не останавливают основной Cloud.ru режим.

## Защита от неправильных весов

- Блоки строк и ячеек сохраняются в отчёт фото как `layout.cellBoxes`, `layout.rowBoxes`, `layout.columnBoxes`.
- Геометрическое сопоставление с OCR допустимо **только** при наличии реального `bbox` самой строки, с пространственным пересечением. Совпадение количества строк не является доказательством.
- Если полная страница не прочиталась, четыре области восстановления охватывают **все** обнаруженные строки; нижняя часть журнала не пропускается.
- Локальный OCR не меняет нетто, брутто, тару или номер автомобиля без подтверждения оператора.
- Не обнаружена сетка — это не ошибка данных: фотография остаётся доступной для PP-StructureV3, PaddleOCR-VL или ручной проверки.

## Тестирование

`npm test` проверяет нормализацию координат, отсутствие выдуманных соответствий и охват строк при восстановлении. `python -m unittest discover -s scripts -p test_grid_geometry.py` (с установленным OpenCV) проверяет геометрию на синтетической таблице и пустой странице. Для оценки точности на рукописных журналах нужны исходные фотографии с вручную отмеченными прямоугольниками ячеек.
