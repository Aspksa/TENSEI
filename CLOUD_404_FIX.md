# Cloud.ru 404 — исправления выбора моделей

**Проблема:** Cloud.ru возвращает 404 на `/v1/chat/completions` для выбранной или автоматически подставленной модели. Повторные фрагменты той же моделью не помогают.

## Корневые причины в коде

1. В режиме `auto` TENSEI не использовал сохранённую модель: подменял её на Qwen3 VL 30B. При недоступности этой модели у пользователя ответ был 404.
2. Резервная модель при 404 автоматически проверялась только при выключенном экономном обработчике. В режимах auto/economy/balanced `fallback` фактически отключался, даже если флажок «Пробовать резервную» был включён.
3. При 404 по умолчанию включалась повторная обработка фрагментов; она вызывала ту же модель/эндпоинт повторно, увеличивая счётчик вызовов без шанса восстановить отсутствующий маршрут.
4. Резервные модели выбирались из устаревающего фиксированного набора. Теперь кандидаты берутся из реального списка `GET /v1/models`, и на резервное чтение допускаются только ID с признаками модели для изображений (VL/vision/OCR). Неизвестные текстовые модели не назначаются автоматически.
5. Проверка подключения раньше показывала сохранённый ID, а не фактический ID при разных режимах стоимости. Теперь проверяется эффективная модель и показывается её имя и доступные в каталоге варианты.

## Использование

1. Откройте TENSEI → Настройки обработки → **Проверить подключение**.
2. Если эффективная модель недоступна, выберите предложенную Cloud.ru VL-модель. TENSEI переключит режим в **Авто**, чтобы использовать этот ID при распознавании.
3. Нажмите **Сохранить**, затем **Проверить подключение** ещё раз.
4. Запустите обработку оставшейся в очереди фотографии. Не выбирайте «обработать все» до проверки на одном файле.

**Важно:** каталог подтверждает только наличие модели для API-ключа. Чтение изображений не проверяется до первого настоящего запроса. Даже существующий в каталоге ID не гарантирует успешное распознавание: Cloud.ru может вернуть ошибки доступа/временной недоступности. TENSEI не выполняет фоновых платных тестов модели без действия пользователя.

## Справка

Официальный API: `https://foundation-models.api.cloud.ru/v1`, методы `GET /models` и `POST /chat/completions`. Требуется ключ от сервиса Foundation Models. Ключ не должен публиковаться в отчётах или GitHub.

CI тестирует mock-404, подбор резервной модели, сохранение статуса ошибки и отсутствие повторных запросов по фрагментам на недоступной модели. Реальный ключ пользователя не запрашивается и не используется.
