# TENSEI · локальные рукописные строки и отдельные ячейки

Выбраны пункты 1–6, 9, 10, 17, 18. Реализация развивает существующий PaddleOCR/OpenCV и не выдумывает распознанные веса.

## Что готово

- OpenCV сначала ищет пересечения линий. Если таблица без линеек, осторожный анализ плотности чернил возвращает *предположительные* границы строк, но **не** рисует неподтверждённые клетки.
- Для таблиц с обнаруженной сеткой эндпоинт `POST /digit-cells` локально вырезает максимум 36 ячеек, увеличивает мелкие фрагменты и запускает PP-OCRv6 отдельно. На каждом фрагменте возвращаются текст, оценка движка и координаты, `verified:false`.
- Кэш на стороне локального сервиса привязан к SHA-256 **точных байтов вырезанного фрагмента**. До 1500 записей, только в памяти процесса; после перезапуска очищается. Никаких переносов распознанного веса между визуально похожими клетками.
- Основная обработка может включить эту проверку через настройку «Дополнительное чтение рукописных цифр». Она сохраняет `digitCells`, `cellConsensus`, `missingRows`, `ocrComparison` и `documentHint` в фотоотчёте. Расхождения не подменяют исходное значение.
- Если модель вернула строку с реальным `bbox`, TENSEI сопоставляет её с геометрией сетки по координатам. Дополнительно помечает обнаруженные строки, не получившие надёжного соответствия.
- При универсальном шаблоне и локально прочитанных заголовках «Тара/Брутто/Нетто» программа автоматически подсказывает колонкам промпта формат весового журнала, не перезаписывая пользовательский шаблон.
- Фото распределяются по датам рейса через `GET /api/photo-groups`, но только если **каждая строка** содержит одинаковую корректную `tripDate`. Иначе фото остаётся «Без даты». Группы видны в аналитике.
- Кнопка «Прочитать ячейки без Cloud.ru» обращается к `POST /api/local-recognize`, работает без API-ключа, возвращает только локальных кандидатов и `cloudCalls:0`. Если сетки нет, показывает распознанные строки текста. Результат **не переносится в реестр** без ручной проверки.
- Уже имеющиеся коррекция контраста, визуальная диагностика перспективы, PP-StructureV3, Chandra и PaddleOCR-VL сохранены. Они могут использоваться совместно для диагностики.

## Как включить

На Windows: установите локальный PaddlePaddle и пакеты `scripts/paddle-requirements.txt` в Python окружение, затем запустите `scripts/paddle_service.py`, слушающий `127.0.0.1:8765`. Для разметки без OCR можно использовать только `scripts/grid-requirements.txt`.

На главном экране загрузите фотографию и нажмите «Прочитать ячейки без Cloud.ru». Для дополнительного локального чтения при обычной обработке раскройте «Настройки» → «Дополнительные режимы распознавания» и включите OCR по ячейкам.

## Не реализовано и почему это важно

- Нет подтверждённого на реальных фото точного детектора **всех** безлинейных ячеек. Для этого нужна разметка исходных фотографий и отдельная обученная модель детекции.
- PP-OCRv6 на отдельной клетке и PP-OCRv6 на всей странице — **не независимые** OCR-модели. Chandra возвращает текст страницы без гарантированного координатного соответствия; PaddleOCR-VL пока выдаёт диагностический результат. Нельзя объявлять большинство по трём моделям подтверждением веса.
- **Полностью локальная авторизация результата** пока не включена. Без облака можно получить и вручную проверить кандидатов; автоматическое внесение веса из этого ответа было бы ненадёжным.
- Улучшение перспективы по OpenCV пока только предлагает предпросмотр, исходник не подменяется без проверки. Нельзя гарантировать, что автоматическая обрезка сохранит все цифры.
- Изображения с плохим контрастом могут не распознаваться даже после коррекции. Точность и экономию измеряют на наборе реальных фотографий с правильными ответами, а не по синтетическим тестам.

Цель следующего этапа: корпус размеченных журналов (строки/ячейки/веса/номера) и измерение точности детекции, CER, ошибок веса и допустимой доли ручных исправлений. Только после этого включать локальную автозамену Cloud.ru.
